# GymTrack

**GymTrack** — облачная платформа (SaaS) для автоматизации фитнес-клубов и мобильное приложение для клиентов на едином бэкенде.

- **Кабинет зала (Business):** управление клиентами (CRM), типами абонементов, кассой и продажами, расписанием, сотрудниками и ролями, аналитикой выручки и посещаемости.
- **Приложение клиента (Client):** профиль, динамический HMAC QR-код для бесконтактного чекина на ресепшене, оформление заявок на абонементы, push/SMS-уведомления, просмотр активных и архивных абонементов, история визитов и покупок по всем залам.
- **Платформа (Platform):** управление тарифными планами залов, биллинг, модерация публичных витрин каталога.

> **Важное бизнес-правило:** в системе **нет онлайн-платежей**. Проводятся только отметки о приёме оплаты сотрудником (`PaymentMark`: наличные, терминал или перевод) с фиксацией ответственного лица и времени.

## Архитектура

Проект построен как **модульный монолит** с соблюдением принципов чистой архитектуры, ООП и SOLID.

```text
app/
├── Modules/                  # Независимые функциональные модули
│   ├── Analytics/            # Сводные отчёты и аналитика зала
│   ├── Audit/                # Неизменяемый журнал аудита событий
│   ├── Billing/              # Тарифы платформы и подписки компаний
│   ├── Clients/              # CRM клиентов, связывание по телефону, слияние дубликатов
│   ├── Companies/            # Залы, сотрудники, роли (RBAC), мультитенантность
│   ├── Identity/             # Аутентификация, SMS OTP, Sanctum токены
│   ├── Memberships/          # Типы абонементов, правила списания, заморозка
│   ├── Notifications/        # Логирование уведомлений, Push/SMS шлюзы, очереди, напоминания
│   ├── Sales/                # Касса, товары, продажи, заявки на абонементы
│   └── Visits/               # Чекин по динамическому QR, ручные визиты, отмена
└── Shared/                   # Ядро: Money, CompanyId, Clock, доменные события, Value Objects
```

### Структура каждого модуля

Каждый модуль изолирован и разделён на слои:
```text
НазваниеМодуля/
├── Contracts/       # Публичные DTO и интерфейсы для взаимодействия с другими модулями
├── Domain/          # Чистый PHP: сущности, Value Objects, правила, события (без Laravel/Eloquent)
├── Application/     # Use Cases (сценарии использования), обработчики событий
├── Infrastructure/  # Eloquent-модели, репозитории, миграции, адаптеры шлюзов
└── Presentation/    # HTTP-контроллеры, FormRequests, консольные команды, маршруты
```

### Ключевые архитектурные правила

1. **Изоляция модулей:** модули общаются **только** через интерфейсы/DTO из папки `Contracts` и доменные события (`DomainEvent`). Прямые связи Eloquent и `JOIN` через границы модулей запрещены и контролируются Deptrac.
2. **Чистый Domain:** доменный слой не содержит зависимостей от Laravel, БД и сторонних пакетов.
3. **Мультиарендность (Multi-tenancy):** данные зала привязаны к `company_id`. В БД наложены составные индексы, изоляция гарантируется `CompanyScope` и проверками в `Policy`. Клиентский аккаунт может иметь карточки в нескольких независимых залах.
4. **Финансы и время:** деньги хранятся целыми числами в минимальных единицах (`Minor Units`) с кодом валюты (`Money`). Время в БД хранится исключительно в UTC.
5. **Надёжность и идемпотентность:** критичные операции (чекин, оформление продажи, заявка) поддерживают заголовок `Idempotency-Key`, выполняются в транзакциях БД с блокировкой строк (`SELECT ... FOR UPDATE`).
6. **Динамический QR:** HMAC-токен с 60-секундным временным окном и валидацией секрета зала.

## Структура API (`/api/v1`)

Все ответы и ошибки API стандартизированы (`{"data": ...}` или `{"error": {"code": "...", "message": "...", "details": ...}}`).

- `/api/v1/business/...` — кабинет зала (авторизация через Sanctum):
  - `/auth/...` — вход по OTP / паролю;
  - `/company/...`, `/gyms/...` — профиль компании, залы, генерация QR;
  - `/clients/...` — создание, поиск, просмотр визитов и покупок клиента, слияние дубликатов;
  - `/membership-types/...`, `/memberships/...` — настройка тарифов, ручная выдача, заморозка, отмена;
  - `/products/...`, `/sales/...` — кассовые операции, товары, возвраты продаж;
  - `/visits/...` — просмотр и ручная фиксация/отмена посещений;
  - `/analytics/...` — отчёты по выручке и посещаемости.
- `/api/v1/client/...` — приложение клиента:
  - `/auth/register` — регистрация клиента (18+, согласие на ПДн, подтверждение номера);
  - `/profile` — просмотр и обезличивание профиля;
  - `/device-tokens` — регистрация и отзыв push-токенов устройств;
  - `/visits/check-in` — отметка посещения сканированием QR;
  - `/membership-requests` — подача заявки на абонемент;
  - `/memberships` — мои абонементы (активные и архивные, по всем залам);
  - `/visits` — история моих визитов с пагинацией;
  - `/purchases` — история моих покупок с детализацией чека.
- `/api/v1/platform/...` — администрирование платформы (активация тарифов подписки, модерация залов).
- `/api/v1/public/...` — публичный каталог залов и абонементов (этап 3).

## Запуск проекта локально (Docker Compose)

### Требования
- Docker Engine 24+
- Docker Compose v2+

### Быстрый старт

1. Склонируйте репозиторий и создайте файл окружения:
   ```bash
   cp .env.example .env
   ```

2. Запустите контейнеры (PHP-FPM 8.3, Nginx, PostgreSQL 16, Redis):
   ```bash
   docker compose up -d
   ```

3. Установите зависимости:
   ```bash
   docker compose exec app composer install
   ```

4. Сгенерируйте ключ приложения:
   ```bash
   docker compose exec app php artisan key:generate
   ```

5. Примените миграции:
   ```bash
   docker compose exec app php artisan migrate
   ```

Приложение доступно по адресу: **http://localhost:8000**  
Health-check эндпоинт: **http://localhost:8000/api/health**

## Фоновые команды и расписание

В системе настроены периодические фоновые команды (`routes/console.php`):

| Команда | Расписание | Описание |
|---|---|---|
| `memberships:expire-due` | Ежедневно в 00:05 UTC | Завершение абонементов с истекшим сроком или исчерпанными занятиями |
| `sales:expire-requests` | Каждые 10 минут | Автоматическая отмена неоплаченных клиентских заявок старше 24 часов |
| `billing:expire-due` | Ежедневно в 00:10 UTC | Завершение истекших пробных периодов (14 дней) и подписок компаний |
| `notifications:send-expiring-reminders` | Ежедневно в 09:00 UTC | Отправка push/SMS-напоминаний клиентам за 7 дней и за 1 день до окончания абонемента |
