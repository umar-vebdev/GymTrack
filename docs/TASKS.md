# GymTrack — чек-лист задач

**Текущий этап:** 0 (каркас проекта)
**Статусы:** `[ ]` не начата · `[~]` в работе · `[x]` готова · `[!]` заблокирована (причина в заметках)

## Правила ведения файла

- Нумерация: `T{этап}-{номер}`, подзадачи `T1-07a`, `T1-07b`.
- Завершённые задачи сворачиваются в одну строку (см. «Готово»), подробности остаются в коммите.
- Подробное описание нужно только для активной и будущих задач **текущего этапа**. Задачи следующих этапов хранятся как эпики и раскрываются перед стартом.
- Одна задача = одна вещь, до ~5 файлов и ~200 строк кода, проверяется одной командой.

### Образец формата задачи

```
- [ ] **T0-00** Короткое название
  - Цель: что должно появиться и зачем
  - ТЗ: Техн. §3.4; Бизнес §4.3
  - Файлы: список создаваемых/изменяемых файлов
  - Шаги:
    1. ...
    2. ...
  - Готово когда: команда и ожидаемый результат
  - Заметки: (заполняется по ходу работы)
```

## Этап 1 — Business (эпики; раскрыть в мелкие задачи перед стартом)

Порядок выполнения (каждый эпик раскрывается отдельно, с подтверждением разработчика):

1. [ ] **E1-A Identity**: регистрация, вход, подтверждение телефона (заглушка SMS-шлюза за интерфейсом), токены
2. [ ] **E1-B Companies**: компания, зал, сотрудники, роли (владелец, администратор), `CurrentCompany`, `CompanyScope`, Policy
3. [ ] **E1-C Audit**: неизменяемый журнал, подписка на события
4. [ ] **E1-D Clients (CRM)**: карточка клиента зала, ручное создание, поиск, связывание по телефону, объединение дубликатов
5. [ ] **E1-E Memberships**: типы абонементов, правила, выдача, заморозка, отмена и возврат (только владелец), статусы
6. [ ] **E1-F Sales**: товары, касса, `PaymentMark`, ручная выдача абонемента
7. [ ] **E1-G Billing**: тарифы платформы, пробный период 14 дней, режим «только чтение» после окончания
8. [ ] **E1-H Analytics**: выручка по отметкам оплаты, посещения, клиенты, популярность
