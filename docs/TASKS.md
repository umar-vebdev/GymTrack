## Правила ведения файла

- Нумерация: `T{этап}-{номер}`, подзадачи `T1-07a`, `T1-07b`.
- Завершённые задачи сворачиваются в одну строку (см. «Готово»), подробности остаются в коммите.
- Подробное описание нужно только для активной и будущих задач **текущего этапа**. Задачи следующих этапов хранятся как эпики и раскрываются перед стартом.
- Одна задача = одна вещь, до ~5 файлов и ~200 строк кода, проверяется одной командой.

## Этап 1 — Business (Identity, Companies, CRM)

4. **E1-D Clients (CRM)**: карточка клиента зала, ручное создание, поиск, связывание
   - [x] **T1-11** Инфраструктура модуля Clients
     - Цель: таблица `clients`, сущность `Client`, репозиторий.
     - Шаги:
       1. Миграция: `id`, `company_id`, `user_id` (nullable), `name`, `phone`, `timestamps`. Уникальный индекс `[company_id, phone]`.
       2. Домен: класс `Client`, интерфейс `ClientRepositoryInterface`.
       3. Инфраструктура: `ClientModel` (с трейтом `BelongsToCompany`), `EloquentClientRepository`.
       4. Настроить `ClientsServiceProvider`.
     - Готово когда: написан модульный тест создания карточки клиента через репозиторий.

   - [ ] **T1-12** Создание карточки клиента (Business API)
     - Цель: эндпоинт создания клиента администратором зала.
     - Шаги:
       1. UseCase `CreateClient` (принимает `name`, `phone`).
       2. Контроллер `CreateClientController` (`POST /api/v1/business/clients`).
     - Готово когда: Feature-тест проверяет успешное создание и отказ, если телефон уже есть в рамках этой компании.

   - [ ] **T1-13** Механизм связывания с пользователем
     - Цель: автоматическое заполнение `user_id` при создании клиента, если юзер уже есть, и при регистрации юзера.
     - Шаги:
       1. Создать контракт в `Identity/Contracts/UserQueryInterface` для поиска пользователя по телефону. Инжектить его в `CreateClient`.
       2. Создать доменное событие `UserRegistered` (в модуле Identity).
       3. Создать Listener `LinkUserToClients` в модуле Clients, который слушает `UserRegistered` и прописывает `user_id` всем `clients` с таким телефоном.
     - Готово когда: тесты подтверждают двустороннее связывание (при создании клиента и при регистрации юзера).

   - [ ] **T1-14** Поиск и список клиентов
     - Цель: эндпоинт `GET /api/v1/business/clients` для списка/поиска.
     - Шаги:
       1. UseCase `SearchClients` (опциональные фильтры `search` по имени/телефону).
       2. Контроллер `SearchClientsController`.
     - Готово когда: Feature-тест ищет клиента по части номера телефона.

   - [ ] **T1-15** Объединение дубликатов (Merge)
     - Цель: возможность слить две карточки.
     - Шаги:
       1. UseCase `MergeClients` (принимает `source_id`, `target_id`).
       2. Удаляет `source_id`.
       3. Контроллер `POST /api/v1/business/clients/merge`.
     - Готово когда: Feature-тест успешно объединяет дубликаты.
