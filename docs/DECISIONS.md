### D-002 — Связывание клиента по событию PhoneVerified, а не UserRegistered
- Дата: 2026-10-23
- Тип: решение
- Решение: карточки привязываются к аккаунту по событию `PhoneVerified` (лежит в `Identity/Contracts`), и при создании карточки — только если у пользователя телефон подтверждён. `UserRegistered` не вводится.
- Причина: Техническое ТЗ 9.3 и Бизнес-ТЗ 4.4 требуют связывание по подтверждённому номеру; привязка по неподтверждённому позволила бы получить чужую историю, указав чужой номер.
- Затронутые разделы ТЗ / задачи: Тех. ТЗ 9.3, Бизнес-ТЗ 4.4, T1-13
- Статус: принято

### D-003 — Валюта типа абонемента по умолчанию TJS (заменено D-008)
- Дата: 2026-10-23
- Тип: решение
- Решение: в `membership_types` хранится собственный код валюты (`currency`). Пока у компании не было настройки валюты, UseCase создания типа подставлял `TJS`.
- Причина: Бизнес-ТЗ 10 — валюта хранится на уровне компании, сомони по умолчанию. Уточнено и заменено полноценной настройкой компании в D-008.
- Затронутые разделы ТЗ / задачи: Бизнес-ТЗ 10, Тех. ТЗ 6.1, T1-17, T1-18, T2-00
- Статус: отменено (см. D-008)

### D-004 — Признак роли «Админ платформы» (`users.is_platform_admin`)
- Дата: 2026-10-28
- Тип: решение
- Решение: для проверки глобальной роли «Админ платформы» (маршруты `/api/v1/platform/...`, подтверждение оплаты подписки зала) в таблицу `users` добавлено булево поле `is_platform_admin` (по умолчанию `false`, не входит в `$fillable` для защиты от массового присвоения).
- Причина: в отличие от ролей сотрудников зала (`owner`, `admin`), привязанных к конкретной компании (`company_id`), «Админ платформы» (Бизнес-ТЗ 2) — глобальная роль команды GymTrack, не привязанная к тенанту.
- Затронутые разделы ТЗ / задачи: Бизнес-ТЗ 1.1, 2; Тех. ТЗ 7.1, 8; T1-39b
- Статус: принято

### D-005 — Жёстко заданные часы работы зала (06:00‑22:00 UTC)
- Дата: 2026-10-30
- Тип: решение
- Решение: для правила `WithinAllowedTimeRule` временно использовался фиксированный диапазон 06:00‑22:00 (UTC).
- Причина: Техническое ТЗ не определяло модель часов на момент старта. Заменено чтением окна времени из абонемента в D-007.
- Затронутые разделы ТЗ / задачи: T2-07, Бизнес‑ТЗ 5.4, Тех. ТЗ 4.4.
- Статус: отменено (см. D-007)

### D-006 — Жёстко заданный дневной лимит посещений = 2
- Дата: 2026-10-30
- Тип: решение
- Решение: правило `DailyLimitNotExceededRule` временно использовало константу `DAILY_LIMIT = 2`.
- Причина: Техническое ТЗ не указывало конкретный лимит на момент реализации; вводилось разумное значение для MVP. Заменено чтением лимита из абонемента в D-007.
- Затронутые разделы ТЗ / задачи: T2-07, Бизнес‑ТЗ 5.4, Тех. ТЗ 5.3.
- Статус: отменено (см. D-007)

### D-007 — Лимит входов в день и окно времени берутся из абонемента (отменяет D-005 и D-006)
- Дата: 2026-10-30
- Тип: решение
- Решение: `WithinAllowedTimeRule` и `DailyLimitNotExceededRule` используют `dailyLimit`, `timeFromMinute`, `timeToMinute` из `MembershipRules` выбранного абонемента (через `CheckInMembershipCandidate` → `CheckInContext`). Без окна времени отметка возможна в любое время; лимит по умолчанию 1.
- Причина: Бизнес-ТЗ 4.3 («лимит входов в день, по умолчанию один»), 5.4 и критерий 12.2 («повторная отметка — занятие не списывается»). Константы из D-005/D-006 противоречили ТЗ. Окно времени сравнивается в UTC (минуты от 00:00); пояс зала для расчёта «дня» (Тех. ТЗ, раздел нефункциональных требований) пока не учитывается — добавить отдельной задачей, когда в `gyms` появится часовой пояс.
- Затронутые разделы ТЗ / задачи: Бизнес-ТЗ 4.3, 5.4, 12.2; Тех. ТЗ 5.3; T2-07
- Статус: принято

### D-008 — Справочник валют (`currencies`), валюта компании (`currency_id`) и получение валюты по умолчанию (уточняет D-003)
- Дата: 2026-10-31
- Тип: решение
- Решение: введена отдельная таблица-справочник `currencies` (`id`, `code`, `name`, `symbol`), в `companies` добавлено поле внешнего ключа `currency_id` (FK на `currencies`, по умолчанию id=1 / TJS). Владелец зала может сменить валюту компании через `PATCH /api/v1/business/company/currency`, а список доступных валют доступен через `GET /api/v1/business/currencies`. Модуль `Companies` предоставляет публичный контракт `CompanyCurrencyLookupInterface`, через который модули `Memberships` и `Sales` при создании типов абонементов и товаров без явного указания валюты берут актуальную валюту компании.
- Причина: закрытие предположения D-003 согласно Бизнес-ТЗ 10 («валюта хранится на уровне компании, сомони по умолчанию») и указанию разработчика.
- Затронутые разделы ТЗ / задачи: Бизнес-ТЗ 10, Тех. ТЗ 3.7, 6.1, D-003, T2-00
- Статус: принято
